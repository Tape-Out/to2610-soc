# to2610-soc 流片说明

流片说明报告（docx）的功能描述、寄存器含义、板级连接、测试说明与局限从这里取，只写在这一处。

## 功能描述

外设齐全的 Linux 系统芯片，面向 ECOS 2610 班车。它是 `to2610-kvc` 那一颗（KianV 的 RV32IMA、Sv32 SoC）在地址图上开了一段窗，窗后面是从组织的 IP 库里用息壤装配出来的十四个外设（MPW 形态另有以太网）。原有的串口、Flash、SDRAM、SD 卡口、SPI 网卡口与 Linux 的启动路径一样不动，同一份镜像照样起得来；新加的外设裸机与 Linux 下都能用。

KianV 的 SoC 是上游的，子模块不动；源码取黑盒仓拼好的那一份，带着它的补丁（修机器态软件中断，以及 riscv-tests 与 riscv-arch-test 查出的与规范不符之处）。本仓自己写的有四样：`patch/soc.patch` 在上游的 `soc.v` 上开地址窗并把片上总线与中断引出来（三十来行）；`hwsrc/kv_apb.v` 把 KianV 的总线转成 APB4；`hwsrc/soc_core.v` 把核、桥与外设块接在一起；`hwsrc/soc_frame.v` 是 Frame 形态的引脚复用。外设块 `soc-io` 是一份息壤的装配清单，没有手写的连线。

### 功能一览

| 项 | 支持 | 说明 |
|:--:|:--:|:--:|
| 处理器、存储、原有外设 | 同 `to2610-kvc` | RV32IMA、Sv32，片外 SDRAM 32 MiB 与 SPI Flash，串口 0（控制台）、SD 卡口、SPI 网卡口、1 位 GPIO |
| 串口 1 | 带 RTS、CTS 流控，收发各 8 字节的队列 | 留给片外的模块：蜂窝模块、WiFi 与蓝牙模块的 AT 口 |
| GPIO 1 | 16 位，逐位方向，上升沿中断 | Frame 形态引出低 12 位 |
| 计时器 | 两路比较、两路输入捕获，16 位预分频 | |
| 看门狗 | 32 位，带窗口 | 到点可出复位脉冲到引脚 |
| 实时时钟 | 64 位计数，一路闹钟 | 掉电不保持：片上没有备份域 |
| I2C | 主机，7 位与 10 位地址 | 开漏，板上要上拉 |
| SPI 2 | 主机，单线全双工，两个片选 | 接屏、传感器，或去管别的芯片的 SPI 管理口 |
| 单总线 | 主机，标准速度，带 CRC-8 | 开漏，板上 4.7 kΩ 上拉 |
| PWM | 4 路，16 位周期与占空 | MPW 形态另出 4 路互补 |
| I2S | 主机，16、24、32 位，收发各一路 | 功放与数字麦克风 |
| CAN | 经典 CAN 2.0B，标准帧与扩展帧，一组验收滤波 | 板上要收发器 |
| PS/2 | 主机，收发 | 5 V 接口，板上要电平转换 |
| 网络 | Frame 形态走 SPI 网卡口接 W5500 模块，同 `to2610-kvc`；MPW 形态另有 `emac`（100 Mbps 的 RMII MAC） | W5500 模块出 8P8C，能直接插 `to2610-switch` |
| 随机数 | 片外噪声源进来，带健康检测与调理 | 只有 MPW 形态与 Frame 的第 3 组引出噪声脚 |
| CRC | 宽度、多项式、初值、反转都可配，到 32 位 | |
| 数字式 ADC 与 DAC | 各两路，一阶 ΣΔ（`hwsrc/sdm.v`）：DAC 出一位的码流，一的密度是 设定值/65536；ADC 靠一根反馈脚把板上电容的电压按在输入脚的门限附近，一个窗口里读到 1 的次数正比于被测电压 | 片上只有数字逻辑，模拟的那一半在板上（见「板级连接」）；精度由板上的电阻电容与输入脚的门限定，适合音频与慢变的电压 |
| 时钟控制 | PLL 的倍频（N、SELECT）与分频（OD，后面再接一级 2 ×（D + 1）），SerDes 的线路时钟在系统时钟与 PLL 分出来的时钟之间无毛刺地切，拿系统时钟量分出来的频率，可以引一根到焊盘上看 | PLL 是 ECOS 的 `PLL_TOP` 硬宏，只有 MPW 形态里有；Frame 形态不许带硬宏，寄存器照样在、读得回来，量到的频率恒是 0 |
| SerDes | 一条全数字的串行通道（`serdes` 仓）：8b/10b 编解码、四倍过采样的接收端从数据里跟时钟、逗号定界、PRBS15 发生与核对、片内自环 | 单端两根脚，线速率是线路时钟的四分之一，Frame 形态下是 12.5 Mbit/s；两颗芯片各用各的晶振也能对接 |

### 外设怎么用

裸机下直接读写下一节那张表里的地址；每个外设的寄存器在它自己仓的 `regmap.yaml` 里，`ran gen <名字>` 出 C 头文件，本仓的整片测试 `htest/xio/xio.c` 就是照这些头文件写的，可以当例程看。

Frame 形态下外设的脚要先选出来：往 `0x4003_0004` 写每根复用焊盘两位的选择（见「板级连接」），再去用对应的外设。复位后 12 根都是 GPIO。

### 启动与软件

启动流程、引导程序、镜像与烧录办法同 `to2610-kvc`：复位后从 Flash 的 `0x2010_0000` 就地执行引导程序，它把紧跟在后面、1 MiB 又 64 KiB 处的载荷搬进 SDRAM 再跳过去。串口 0 是默认的调试输出与控制台，115200。按住复位时全部引脚高阻，烧录器夹上 Flash 就能在板写。

这一版 Linux 下还没有新外设的驱动与设备树结点，用 `devmem` 直接读写寄存器（镜像里有）。

## 寄存器

KianV 原有的地址见 `to2610-kvc` 的流片说明。窗在 `0x4000_0000`，核对这一段的读写原样变成 APB4 的传输；窗里没有东西的地方读回 0、写了不管，不陷入。

| 地址 | 外设 | 中断（PLIC 的号） |
|:--:|:--:|:--:|
| `0x4000_0000` | 串口 1（`uart`） | 11 |
| `0x4000_1000` | GPIO 1（`gpio`） | 12 |
| `0x4000_2000` | 计时器（`timer`） | 13 |
| `0x4000_3000` | 看门狗（`wdt`） | 14 |
| `0x4000_4000` | 实时时钟（`rtc`） | 15 |
| `0x4000_5000` | I2C（`i2c`） | 16 |
| `0x4000_6000` | SPI 2（`spi`） | 17 |
| `0x4000_7000` | 单总线（`onew`） | 18 |
| `0x4000_8000` | I2S（`i2s`） | 19 |
| `0x4000_9000` | CAN（`can`） | 20 |
| `0x4000_A000` | PS/2（`ps2`） | 21 |
| `0x4000_B000` | 随机数（`rng`） | 22 |
| `0x4000_C000` | 以太网（`emac`），帧缓冲区在 `0x4000_D000`；只在 MPW 形态里，Frame 形态读回 0 | 23 |
| `0x4000_E000` | PWM（`pwm`） | 无 |
| `0x4000_F000` | CRC（`crc`） | 无 |
| `0x4001_0000` | SerDes（`serdes_apb`），寄存器见 `serdes` 仓的自述 | 27 |
| `0x4002_0000` | 数字式 ADC 与 DAC（`sdm`），寄存器见 `hwsrc/sdm.v` 开头 | 无 |
| `0x4003_0000` | 标识，只读，`0x534F4331` | |
| `0x4003_0004` | 引脚复用 `PADSEL`：第 2k+1:2k 位选第 k 根复用焊盘的功能，复位全 0 | |
| `0x4005_0000` | 时钟控制（`clkctl`），寄存器见 `hwsrc/clkctl.v` 开头 | 无 |

PLIC 的 10 号仍是串口 0。

`sw/` 下的脚本：`flash.sh`、`console.sh` 在电脑上烧 Flash、开串口；`padsel.py` 在电脑上算 `PADSEL`；`xio.sh`、`clkctl.sh`、`serdes.sh` 在芯片上的 Linux 里用（busybox 带 `devmem`），依次是读写窗里的寄存器、设 PLL 与分频并量频率、SerDes 的自环与误码测试。

## 板级连接

payload 的前 54 位与 `to2610-kvc` 逐位相同（串口 0、Flash、SDRAM、SD 卡口、SPI 网卡口、1 位 GPIO），两颗芯片用同一块底板，接法见 `to2610-kvc` 的流片说明。余下 12 位（payload 第 54 至 65 位，下面叫 x0 至 x11）每位四选一：

| 焊盘 | payload 位 | 0（复位） | 1 | 2 | 3 |
|:--:|:--:|:--:|:--:|:--:|:--:|
| x0 | 54 | GPIO 0 | 串口 1 TXD | — | SPI 2 SCK |
| x1 | 55 | GPIO 1 | 串口 1 RXD | — | SPI 2 CS0_N |
| x2 | 56 | GPIO 2 | 串口 1 RTS_N | — | SPI 2 MOSI |
| x3 | 57 | GPIO 3 | 串口 1 CTS_N | — | SPI 2 MISO |
| x4 | 58 | GPIO 4 | I2C SCL | — | SerDes TX |
| x5 | 59 | GPIO 5 | I2C SDA | — | SerDes RX |
| x6 | 60 | GPIO 6 | 单总线 | — | SPI 2 CS1_N |
| x7 | 61 | GPIO 7 | CAN TX | PWM 0 | I2S SCK |
| x8 | 62 | GPIO 8 | CAN RX | PWM 1 | I2S WS |
| x9 | 63 | GPIO 9 | PS/2 时钟 | PWM 2 | I2S SD 出 |
| x10 | 64 | GPIO 10 | PS/2 数据 | PWM 3 | I2S SD 入 |
| x11 | 65 | GPIO 11 | 计时器捕获 0 | 看门狗复位出 | 随机源入 |

payload 第 n 位是 MPC-Frame 的 `user_io[n + 7]`；逐位的完整位表在报告的「payload 位表」里。

- 时钟 50 MHz。
- 入网：SPI 网卡口接 W5500 模块，接法与镜像里的驱动都同 `to2610-kvc`。第 2 组的 x0 至 x6 在 Frame 形态里没有功能，选了输出 0。
- 开漏的脚（I2C 两根、单总线、PS/2 两根）各要一颗上拉：I2C 与单总线 4.7 kΩ 到 3.3 V；PS/2 是 5 V 接口，要过电平转换。
- CAN 的 TX、RX 接一颗 3.3 V 的收发器（SN65HVD230 一类）。
- 串口 1 接片外模块的主串口，四根线交叉接（TXD 对 RXD，RTS_N 对 CTS_N）。
- 数字式 ADC 与 DAC：`sdm` 的 PINS 位一开，x6 至 x11 在第 0 组里依次是 DAC0、DAC1、ADC0 的反馈、ADC0 的输入、ADC1 的反馈、ADC1 的输入。DAC 脚后面接一颗电阻一颗电容（如 1 kΩ、100 nF）就是电压，接音频要再隔直；ADC 每路两颗等值电阻（如 10 kΩ）分别从被测电压与反馈脚汇到一颗电容（如 1 nF）上，电容接输入脚。读数是相对电源电压的比例，输入脚的门限偏离一半电源时有固定的偏差，要用已知电压校一次。
- SerDes：两颗芯片对接时 TX 对 RX 交叉接，共地，线尽量短（单端 3.3 V 电平，没有差分驱动与均衡）；自己测自己就把 x4 与 x5 短接。
- 没选到焊盘上的外设，输入拿到的是空闲电平，不会误动作。
- 复位：按住复位时全部 payload 脚高阻。

## 测试说明

测试台 `tb.cpp` 来自黑盒仓，跑在 Verilator 上，带 SDRAM、Flash、串口的引脚级模型。被测的是 `ran asic` 出的那份交付文件。12 根复用焊盘在测试台上按选中的功能组接回环或最小的片外模型（`htest/shim.py`）。

| 用例 | 测什么 |
|:--:|:--:|
| hello、periph、isa、arch-test、boot | `to2610-kvc` 的五段原样再跑（裸机冒烟、原有外设、riscv-tests 七十九个、riscv-arch-test 七十一个、引导程序）：开了地址窗、接了外设之后，原有的通路与核的行为不许变 |
| rtos、image | `to2610-kvc` 的 FreeRTOS 冒烟原样在这一颗上跑；它的 Linux 镜像先在 QEMU 上起到 shell |
| linux | 同一份镜像在这一颗上从 Flash 引导到 shell、跑那组命令。这一颗的仿真每秒十几万拍，起一遍要十个小时上下，一个作业放不下：流水线上整片测试把仿真器、镜像与脚本交给后面六棒接力（`htest/linux-boot.sh`），每棒跑满四个半小时存断点，下一棒从断点接着同一份脚本往下走，最后一棒报结果；本机带 `SOC_LINUX=1` 一口气跑 |
| linux-onchip | 从接力起到 shell 时存的断点接着跑：SD 卡上放 `sw/` 下的三个片上脚本，在 Linux 里各跑一遍：地址窗标识、SerDes 片内自环一秒零误码、时钟分频设了再读回 |
| linux-net | 同一断点接着跑 `to2610-kvc` 的网络四段：SD 卡读写与 md5；SPI 网卡口上的 W5500 拿到地址、ping 通测试台里的主机；网线接到 `to2610-switch` 两颗夹 `to2610-router` 的联合仿真上，同网段与过路由器都 ping 通；经宿主机 NAT 取文件核 md5、查 DNS、按名字取网页 |
| xio：地址 | 窗里的空地址读回 0；六个外设的复位值各不相同、逐个读对；十四个实例各写一个不同的数（以太网那一页读回 0），全部写完再读回，两个实例译到同一页或哪一页没人应就对不上 |
| xio：GPIO | 对接的两组脚互相读到、松手后是上拉；上升沿中断经 PLIC 的 12 号进来 |
| xio：串口 1 | 500 千波特发四个字节，从回环收回来，流控开着；发送水位中断经 11 号进来 |
| xio：单总线 | 发复位，板上的器件应存在脉冲 |
| xio：PS/2 | 板上的设备送来扫描码 0x1C |
| xio：SPI 2 | 板上的回声从设备每个字节回上一个字节的反码，片选在四个字节之间按着不放 |
| xio：I2S | SD 出接回入，左右声道各收回发出去的数 |
| xio：SerDes | 片内自环发四个字节、原样收回，收到字节的中断经 27 号进来；再经焊盘 x4 出、x5 回跑 PRBS，零误码；线上翻一位，记到错 |
| xio：数字式 ADC 与 DAC | 六根脚接管 GPIO；板上第 0 路 ADC 量四分之一满幅的直流、第 1 路量第 0 路 DAC 的码流，两个读数都在该在的地方 |
| xio：计时器 | 数到比较值，中断经 13 号进来 |
| xio：时钟控制 | 标识、复位值、读写；Frame 形态里量到的频率是 0 |
| av-tone | `sw/av/tone.c` 原样编（仿真里只缩短等待）：x7 至 x10 选给 I2S，1 kHz 正弦经板上的回环收回来，峰值与发出去的相同；一帧 61 µs，采样率 16.3 kHz |
| av-sdm | `sw/av/sdm.c`：数字式 ADC 量 DAC 的码流与四分之一满幅的直流，自检读数对得上，之后每半秒报 825 mV |
| clkctl | 时钟控制配上 PLL 的行为模型与 SerDes 单独测，两颗「芯片」各用各的晶振（差 600 ppm）：旁路时量到参考时钟的一半；五组倍频与分频各自量到该有的频率，不合法的组合量到 0；`clk_out` 脚；SerDes 换到 PLL 的时钟上自环；两颗在 25 Mbit/s 与 12.5 Mbit/s 上对接跑 PRBS，零误码；两边速率不同锁不上；切回系统时钟照样通。再埋九处错，每处都要红。PLL 的模型是照 ECOS 公开的接口说明写的，换上 ECOS 自己的行为模型结果相同 |
| onchip-scripts | `sw/` 里在芯片上用的三个脚本与 `padsel.py`，在主机上拿一个假的 `devmem` 过一遍（照寄存器说明另写的模型，PLL 照宏的规矩只在 EN 拉起时取设置）：每条命令的读数与该有的相同，没有时钟时拒绝切线路时钟。再埋六处错，每处都要红 |
| sdm | `sdm` 单独测：DAC 六万五千五百三十六个节拍里一的个数正好等于设定值；ADC 输入钉高钉低正好是满与零，三个直流电平差不过 4；ADC 量 DAC 的闭环。再埋八处错，每处都要红 |
| xio：I2C | 板上地址 0x50 的从设备读出 0xA5，0x51 没人应 |
| xio：CAN | 发一帧，TX 接回 RX、线上没有别的节点，记的是应答错 |
| xio：计时器捕获 | 捕获脚接着串口 1 的 TXD，停止位的上升沿把计数器抓进去 |
| xio：PWM 与看门狗复位出 | 五根脚选到第 2 组、经板上接回 GPIO：四路 PWM 逐路拉高读到 1、2、4、8；看门狗数完复位出拉高，关掉落下 |
| xio：SPI 第二根片选 | 从设备被第二根片选选中时回原码 |
| xio：随机数 | 噪声脚上是伪随机码流，启动自检过、出得来数 |
| pin-faults | 把 `hwsrc/soc_frame.v` 里的脚逐根接错（悬空、两根对调、拿错焊盘，十八处）、重出 `.v` 再跑 xio：管那根脚的那一句要红，跑到一半卡住而那一句还没报 ok 的也算红 |
| xio：CRC | CRC-8/MAXIM-DOW 算 `123456789` 得 0xA1 |

外设各自的功能在各自的仓里测（配置矩阵、行为测试、变异）；整片这一层验的是只有这一层才会错的三样：地址、引脚、中断号。

## 局限

- 同 `to2610-kvc` 的各条：缓存旁路、主频固定 50 MHz、没有 JTAG。
- I2C、CAN、PWM、看门狗、实时时钟、随机数这六个在整片上只核到寄存器读写，引脚没有接片外模型测过。
- Frame 形态一次只能引出 12 根外设脚，GPIO 1 的高 4 位、PWM 的互补输出、计时器的第二路捕获引不出来。
- SPI 2 是单线全双工。IP 的多线档每一帧只发或只收、不能逐帧换协议，接不了要先发单线命令的 QSPI Flash，所以没有用。
- Linux 下新外设还没有驱动，只能经 `/dev/mem` 读写。
- USB 没有做。
